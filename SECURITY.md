# Vervain Context Firewall: Deterministic Security Invariants & Attack Matrix

**Scope boundary:** This document specifies the 15 of 15 repository-scoped architectural invariants, the 7-surface adversarial mitigation matrix, and the explicit residual risks for the `vervain-context-firewall` single-service prototype (`MEDIATED_BOUNDARIES`: `2` of `2` application boundaries in this demo, `retrieval_to_gemini_context_envelope` and `gemini_response_to_browser_release`). Authorization is deterministic TypeScript server code; Google Gemini is never consulted as a permission oracle.

---

## 1. Non-Negotiable Deterministic Invariants (1 through 15)

All 15 of 15 invariants are enforced or explicitly bounded in server code inside `/Users/pjmullin/Desktop/vervain-carbon-demo/src`:

1. **Server-Owned Tenant & Principal Authority (Invariant 1 of 15):** Tenant identity (`tenantId`), principal (`principalId`), policy identifier (`policyId`), active epoch (`policyEpoch`), and 32-bit request scope tag (`requestScopeTag`) are derived exclusively from `SessionStore` (`src/server/session.ts:resolveCookieToken`). Any request header, query parameter, or JSON body field matching the 25 of 25 normalized override keys in `src/shared/contracts.ts:detectClientAuthorityOverride` is rejected with HTTP `400` (`authority_override_rejected`).
2. **Immutable Provenance & Digest Binding (Invariant 2 of 15):** Every stored record in `FROZEN_RECORDS` (`2` of `2` synthetic server records in `src/server/fixture.ts:makeStoredRecord`) is frozen with `tenantId`, `sourceId`, `sourceVersionSha256`, `contentSha256`, `classification`, and `policyEpoch`.
3. **Tenant-Scoped Default Retrieval vs Confined Synthetic Defect (Invariant 3 of 15):** Ordinary retrieval (`src/server/retrieval.ts:retrieveTenantScopedChunks`) enforces 3 of 3 store predicates (`tenantId`, `policyEpoch`, and destination `classification`). The defective retriever (`src/server/retrieval.ts:retrieveBrokenControlChunks`) accepts only the literal `'cross_tenant_filter_omission'` inside `runPairedProofWorkflow` and cannot be enabled via environment flags or user parameters on governed routes.
4. **Independent Fail-Closed Context Admission Gate (Invariant 4 of 15):** `src/server/admission.ts:evaluateContextAdmission` independently validates 100% of candidate chunks across 6 of 6 ordered checks regardless of retriever behavior. Foreign, stale-epoch, digest-mismatched, unrecognized, disallowed-classification, oversized (`> 4096` UTF-8 bytes), or excess (`> 4` admitted chunks per request) items are `withheld`; malformed or incomplete items become `unknown`. Zero missing-metadata items are silently admitted.
5. **Admitted-Only Outbound Gemini Envelope (Invariant 5 of 15):** `src/server/envelope.ts:buildVervainGeminiEnvelope` accepts only `AdmittedChunk[]` carrying both a compile-time `unique symbol` brand and a runtime `WeakSet` registration (`src/server/admission.ts:isVerifiedAdmittedChunk`). `SpyGeminiTransport` (`src/server/gemini.ts`) captures deep-frozen outbound envelope snapshots immediately before transport execution so automated suites verify exact chunk membership.
6. **Pre-Release Authority & Policy-Epoch Recheck (Invariant 6 of 15):** Immediately before returning any model output, `src/server/release.ts:ResponseReleaseGate.evaluateRelease` reloads the live session from `SessionStore` and verifies continuity across 5 of 5 session bindings (`sessionId`, `tenantId`, `principalId`, `stateGeneration`, and `policyEpoch`) plus non-expiration. An epoch increment or session expiration during generation withholds the reply (`policy_epoch_changed` or `session_expired`).
7. **Untrusted Model Output & Inert Document Directives (Invariant 7 of 15):** Embedded document override strings (`BEACON_RECORD`) are formatted strictly inside quoted data delimiters (`src/server/envelope.ts:formatUserContent`), and Gemini output is parsed strictly as `{ answer: string, sources_used: string[] }` (`src/server/gemini.ts:parseStructuredModelJson`) capped at `8192` UTF-8 bytes. Zero tools, shell commands, authority mutations, or durable memory writes execute from model output across 100% of server routes.
8. **Bounded Secondary Planted-Value Instrumentation (Invariant 8 of 15):** Exact substring scanning for `SYNTHETIC_PLANTED_VALUE` (`BEACON_PROJECT_EMBER_742` in `src/server/release.ts:containsPlantedValue`) serves solely as bounded impact instrumentation and a secondary release tripwire (`planted_value_detected`). Primary enforcement is structural provenance exclusion prior to provider dispatch; absence of the exact token does not establish absence of semantic paraphrase.
9. **Content-Free Bounded Receipts (Invariant 9 of 15):** `ContextReceipt` (`src/server/receipts.ts:buildAndAppendRunReceipt`) stores domain-separated SHA-256 digests, integer denominators, fixed reason codes, latency/retry metadata, and boundary exclusions. Before ledger persistence, `src/server/redaction.ts:findProhibitedContentInObject` recursively scans 100% of receipt keys and string values to block raw fixture text, queries, model answers, planted values, session IDs, cookies, and API keys (`0` protected content bytes stored).
10. **Live-Instance Tamper-Evident Receipt Chain (Invariant 10 of 15):** `AuditLedger` (`src/server/ledger.ts`) links 6 of 6 stage events per run from `GENESIS_CHAIN_SHA256` and binds event slices plus `previous_receipt_chain_sha256` into `current_receipt_chain_sha256` over canonical sorted-key JSON (`canonicalJsonString`). `AuditLedger.verifyChain()` detects in-memory mutation or event reordering within the live process, while explicitly stating that full-store rollback across restarts requires an external checkpoint (`rollback_note`).
11. **Finality of Native Denial (Invariant 11 of 15):** Vervain narrows allowances and never widens denials. When 0 of `N` candidate chunks satisfy `gemini.context` admission (such as Tenant Beacon whose sole fixture record carries `restricted-strategy`), `executeVervainGovernedArm` skips provider invocation (`provider_not_called`, `no_context_admitted_native_denial_preserved`).
12. **Mandatory Paired Forbidden & Permitted Twins (Invariant 12 of 15):** `runPairedProofWorkflow` (`src/server/workflows.ts`) executes both arms against the same frozen query (`FROZEN_QUERY_SHA256`) and broken retrieval batch (`2` of `2` records): `Native only` demonstrates `cross_tenant_context_transmitted` (`2` of `2` chunks in envelope), whereas `Native + Vervain` withholds the `1` of `2` foreign Beacon chunk (`tenant_mismatch`) and completes the `1` of `2` authorized Alder renewal answer (`permittedTaskCompleted: true`).
13. **Explicit Mediation Perimeter & Exclusions (Invariant 13 of 15):** Every receipt embeds the exact `2` of `2` mediated boundaries (`MEDIATED_BOUNDARIES`) alongside `7` of `7` explicit exclusions (`RECEIPT_EXCLUSIONS` in `src/shared/config.ts`), leaving provider-internal KV state, direct unmediated SDK calls, external databases, and host administrators explicitly outside the mediated boundary.
14. **Bounded Claim & Vocabulary Discipline (Invariant 14 of 15):** UI labels, receipts, and repository docs report only observed or deterministically enforced outcomes on named configurations, pairing every metric with its denominator and scope boundary while avoiding unbounded protection, hidden-reasoning, universal prompt-injection, tensor-erasure, regulatory, or third-party attestation claims.
15. **Fail-Closed Scoped Attention & Self-Hosted Binding Posture (Invariant 15 of 15):** In this web service, `src/server/scoped-attention.ts:runReferencePagedAttention` binds `requestScopeTag` strictly from server session authority, fails closed on invalid block IDs (`failed_closed_invalid_block_id`), non-finite vectors (`failed_closed_invalid_input`), and all-masked rows (`refused_all_masked`), and displays `SCOPED_ATTENTION_LIMITATION_LABEL`. Any separate self-hosted vLLM / H200 artifact (Carbon 2 lane) remains `NO GPU RUN RECORDED` until an authorized run binds exact vLLM SHA, patch SHA, runtime-selected backend, physical block ID, allocation generation, and paired sample denominators after owner `GPU GO`.

## 3. Explicit Residual Risks

Even when 100% of automated unit, integration, adversarial, and end-to-end checks pass, the following residual risks remain inherent to this prototype's architecture and are surfaced directly to judges in `RECEIPT_EXCLUSIONS` and `CLAIMS.md`:

1. **Hosted Provider Internals Are Unmediated:** Once admitted Tenant Alder chunks cross into `OfficialGoogleGenAITransport` (`@google/genai`), Google Gemini's internal KV caches, batching scheduler, model weights, and provider infrastructure lie outside customer-side runtime inspection. Vervain governs what enters the outbound request envelope, not internal provider memory.
2. **Application Bypass Outside This Service:** Vervain mediates only the `2` of `2` boundaries wired through `src/server/workflows.ts`. Any developer script, background worker, external MCP tool, or microservice that calls `@google/genai` or queries a backing store directly bypasses both `evaluateContextAdmission` and `ResponseReleaseGate`.
3. **Semantic Paraphrase Beyond Exact Planted-Value Match:** If an authorized chunk itself contained sensitive material that was erroneously classified as `customer-commercial`, or if a control test evaluates subtle paraphrasing rather than exact substring presence of `BEACON_PROJECT_EMBER_742`, `ResponseReleaseGate.containsPlantedValue` will not detect paraphrased disclosure. Structural provenance withholding before inference (`evaluateContextAdmission`) is the primary defense, and depends on accurate server-side tenant and classification tagging at ingest.
4. **Nonstreaming Time-to-First-Token (TTFT) Tradeoff:** `ResponseReleaseGate` buffers the complete JSON generation (`geminiMaxOutputTokens = 256`) so policy-epoch continuity (`policy_epoch_changed`) and exact planted-value checks execute before a single response byte reaches the browser. Token streaming is intentionally omitted in this prototype, trading higher TTFT for pre-release gate completeness.
5. **Ephemeral In-Memory State & Rollback Horizon:** Both `SessionStore` and `AuditLedger` reside in process RAM without an external database or transparency log checkpoint. While `AuditLedger.verifyChain()` detects single-event mutation or swap within the live container, a full Cloud Run container restart clears history and resets the chain head to `GENESIS_CHAIN_SHA256`.
6. **Synthetic Persona Selector vs Production Identity:** `POST /api/demo/session` binds a public visitor to synthetic `alder` or `beacon` fixtures without a password or OIDC token so judges can inspect multi-tenant behavior in 60 seconds. Real deployments must bind `SessionStore` authority from verified upstream OIDC/SAML/workload credentials rather than a public persona picker.
7. **Reference Scoped Attention vs GPU Kernel Enforcement:** `src/server/scoped-attention.ts` validates the pre-softmax scope-masking equation on deterministic 4-dimensional CPU arrays in TypeScript. It does not patch vLLM's CUDA/Triton paged-attention kernels, prevent GPU side-channel timing, or erase freed HBM tensor bytes; production-path vLLM enforcement belongs strictly to the separate Carbon 2 worktree and requires an independently verified artifact after owner `GPU GO`.
