# Carbon Lane & Daybreak Integration Guide

This document defines how **Carbon 1 (Lead Application)**, **Carbon 2 (vLLM Inference Patch Lane)**, and **Daybreak** consume and produce Vervain evidence artifacts verified by **Carbon 3 (`vervain-evidence-verifier`)**.

## 1. Separation of Concerns (Never Self-Verify)

1. The Lead Application must **never** determine pass/fail from its own React UI summary flags, screenshots, or simulated counters.
2. Any Vervain evidence badge in the Lead Application must display `verified_evidence_status`, `verdict`, `primary_reason_code`, and `claim_boundary` verbatim from `verifier-result.v1` produced by `evidence-verifier`.
3. `local_only` or `incomplete` artifacts MUST render as `NO VERDICT` (`exit 2`), never green/passing.

## 2. TypeScript / Lead App Integration (`@vervain/evidence-verifier`)

Build the TypeScript companion first (`packages/evidence-verifier/ts`):

```bash
tsc -p packages/evidence-verifier/ts/tsconfig.json
```

Exports in `packages/evidence-verifier/ts/src/index.ts`:

- `parseStrictJson(rawText)` -> rejects duplicate keys, `__proto__`/`constructor`/`prototype`, non-finite numbers, `-0.0`, integer overflow, lone surrogates, NUL bytes.
- `canonicalizeJcs(value)` -> deterministic RFC 8785 JCS serializer.
- `computeArtifactSha256(artifact)` -> independent SHA-256 matching Python `strict_json.py`.
- `sanitizeStructure(data)` -> zero-echo check for forbidden keys, API/PEM/Bearer tokens, PII, IPv4, and synthetic canary strings before UI rendering.
- `verifyArtifactDigestAndSummaryLocal(rawJsonText)` -> fast in-process pre-check verifying strict JSON, JCS digest, sanitizer, `evidence_status` cap (`NO VERDICT` for `local_only`/`incomplete`), and `ui_summary` raw cross-check.
- `runPythonVerifierCli({ verifierPackageSrc, artifactPath, runDir, trustRootPath, requireSignature })` -> executes the authoritative Python verifier CLI as a bounded child process and parses `VerifierResultV1` (`PASS` / `FAIL` / `NO VERDICT` / `ERROR`).

Always treat `runPythonVerifierCli` (full invariant + schema + Ed25519 + TP rank + KV generation verifier) as the authoritative verdict source for display in the Evidence Verification drawer.

## 3. Producer `RUN_DIR` Contract (Carbon 2 -> Carbon 3)

For a single-H200 (`tp_size=1`) or 8xH200 (`tp_size=8`) run to satisfy `verify-run`, the run directory (`RUN_DIR`) must contain exact-once regular files with no symlinks escaping `RUN_DIR` and no shadow backups:

```text
<RUN_DIR>/
  manifest.json                  # run-manifest.v1 + disk_manifest entries
  artifact.json                  # inference-proof.v1 artifact (signed when trust root is used)
  artifact.sig                   # optional detached Ed25519 signature envelope
  sources/
    vllm.patch                   # exact unified diff hashed against patch_sha256
    source_hashes.json           # expected SHA-256 map for tracked files under sources/tracked/
    tracked/...                  # verified copy of patched Vervain source files
  logs/
    events.jsonl                 # per-step scope_decision + block_lifecycle records
    dispatch_spans.jsonl         # per-request, per-rank backend dispatch/non-dispatch spans
  ranks/
    rank_0.json ... rank_{TP-1}.json
  receipts/
    commands/
      01_*.json ...              # command-receipt.v1 generated by verification/run_wrapped.py
```

Wrap every launch step with `verification/run_wrapped.py` so `git_sha`, `git_dirty_before/after`, redacted `argv_sanitized`, sanitized environment digest, `stdout_sha256`, `stderr_sha256`, exit code, and `receipt_sha256` are recorded deterministically:

```bash
python3 verification/run_wrapped.py \
  --step-id 02_fault_probe \
  --run-id "$RUN_ID" \
  --receipt-out "$RUN_DIR/receipts/commands/02_fault_probe.json" \
  --stdout-out "$RUN_DIR/logs/02_fault_probe.stdout.log" \
  --stderr-out "$RUN_DIR/logs/02_fault_probe.stderr.log" \
  --expected-file "$RUN_DIR/proof.json" \
  -- <command ...>
```

For negative control steps that intentionally exit non-zero, pass `--expected-nonzero-control`. Never pass secrets via raw CLI flags without review; `run_wrapped.py` redacts known sensitive flags (`--api-key`, `--token`, `--secret`, `--password`, etc.) and redacts all sensitive environment variables while preserving only allowlisted safe variables (`VLLM_ATTENTION_BACKEND`, `CUDA_VISIBLE_DEVICES`, `VLLM_USE_V1`, etc.).

## 4. Daybreak Security Loop Integration

Daybreak schedules and runs:

1. **Offline CI Gate (Always Allowed)**:
   ```bash
   PYTHONDONTWRITEBYTECODE=1 python3 verification/run_local_gates.py
   ```
   Verifies AST/annotations, syntax compilation, pyflakes, TypeScript build, 40+ unit/property/mutation/snapshot tests, secret scan, and offline dependency hygiene.

2. **Adversarial Self-Test Before Accepting Any Artifact**:
   ```bash
   PYTHONPATH=packages/evidence-verifier/src python3 -m evidence_verifier mutate "$PROOF_JSON" --campaign all --trust-root "$TRUST_ROOT"
   ```
   Confirms `all_passed == true` across all 31 security-critical mutations against the supplied baseline.

3. **Bounded Post-Run Verification (`verify-run`)**:
   ```bash
   bash verification/verify_h200_run.sh "$RUN_DIR" --trust-root "$TRUST_ROOT" --require-signature
   ```
   Emits sanitized `<RUN_DIR>/verification.json` (`verifier-result.v1`) and `<RUN_DIR>/verification.md`, returning deterministic exit code `0` (`PASS`), `1` (`FAIL`), `2` (`NO VERDICT`), or `3` (`ERROR`).

4. **Zero-Echo Safety Guarantee**:
   If `--forbidden-strings-file` is passed with synthetic canary tokens used in a test run, `verify` and `verify-run` verify neither raw values nor hex/base64/base64url encodings exist anywhere in `proof.json`, `logs/`, `receipts/`, or rendered outputs.
